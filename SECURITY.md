# Security Policy

## Reporting a vulnerability

Please do not publish exploitable security details in a public issue.

Use GitHub private vulnerability reporting when available. If private reporting is unavailable, contact the maintainer through the GitHub profile associated with this repository and clearly mark the message as a security report.

Include the affected component, version or commit, reproduction steps, realistic impact, and a suggested mitigation if known.

## Sensitive data

Never include real customer financial data, government identifiers, credentials, API keys, payment data, credit reports, or private provider payloads in issues, pull requests, screenshots, fixtures, or logs.

## Production use

This repository is a reference implementation. Production deployments require their own threat model, retention rules, access controls, audit logs, consent model, encryption, provider verification, incident response, and jurisdiction-specific compliance review.
