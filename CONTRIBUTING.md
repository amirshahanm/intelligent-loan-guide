# Contributing

Thanks for helping improve Intelligent Loan Guide / TashilRadar.

## Before opening a PR

1. Search existing issues and pull requests.
2. Keep changes focused and explain the user or maintainer problem being solved.
3. Do not add secrets, credentials, real customer data, or private financial records.
4. Preserve Persian RTL behavior and mobile usability.
5. Keep mocked and real integrations clearly separated.

## Local checks

```bash
bun install
bun run lint
bun run build
```

## Pull request expectations

Describe what changed, why it changed, screenshots for visual changes, privacy/security implications, mocked versus real integration behavior, and verification performed.

Good contribution areas include accessibility, RTL quality, explainability, testing, provider abstractions, privacy, security hardening, documentation, and performance.

Large architectural changes should start as an issue so trade-offs can be discussed first.
